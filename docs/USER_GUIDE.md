# Color Palette Creation — User Guide

This project turns **(1) an original image** + **(2) a marked-up image** into:
- a per-image **PDF report**
- per-swatch **paint mix recipes** (based on your configured paint set)
- optional **palette swatch images**
- optional **Google Drive upload**

It also includes:
- a **Web UI** (upload + browse + paint editor + local-color tools)
- a **Telegram intake bot** (send original + marked; optional skin/local workflow)

---

## Mental model (what the system does)

1) You provide two images with the same dimensions:
   - `BASE.jpg` (original)
   - `BASE_x.jpg` (marked)

2) The worker compares them and finds the regions you marked (difference areas).

3) For each region, it samples the dominant color from the **original** image under that marked area.

4) Each sampled color becomes a **target swatch**. The solver finds a paint recipe (percentages of your configured paints) that best approximates that target.

5) It writes outputs under:

```
/mnt/out/BASE/
  BASE_report.pdf
  charts/
  palettes/
  BASE_local_skin.json          (only for skin mask flow)
  BASE_local_skin_pie.png       (generated on demand by UI)
  BASE_local_skin.json
  .drive_upload.json            (written after successful Drive upload)
```

6) Optionally, after a batch completes, it uploads outputs to Drive via `rclone`.

---

## Components

### 1) Worker (watcher)
- Long-running process in Docker.
- Watches an input folder for ready pairs.
- Produces outputs + optionally archives inputs.

### 2) Web UI
- Runs on port `4040`.
- Lets you upload the two images without touching network folders.
- Provides paint palette editing and local-color utilities.

### 3) Telegram bot
- Lets you run the workflow from Telegram.
- You send ORIGINAL then MARKED.
- Bot writes files into the same input folder as the UI.

## Typical workflow

### A) Use the Web UI (recommended)
1) Open:
   - `http://<host>:4040/`

2) Upload:
   - Original image
   - Marked image
   - (Optional) Base name

3) Choose **Mask type**:
   - **General**: normal swatches + mixes
   - **Skin**: additionally computes a single “local skin color” (combined from all swatches) + one paint recipe for that local color.

4) After upload, you’ll be taken to:
   - `/jobs/<base>`

This page auto-updates and will auto-open the PDF when ready.

5) Browse all runs:
   - `http://<host>:4040/runs`

---

### B) Use Telegram intake bot
Send one of:
- `/palette` (auto-name)
- `/palette example` (your base name)
- `/palette skin` (auto-name + skin mask flow)
- `/palette example skin` (your base name + skin mask flow)

Then:
1) Send ORIGINAL image (as a **Document** is strongly recommended to avoid Telegram downscaling)
2) Send MARKED image

The bot will notify you when:
- the PDF exists
- and when Drive upload is confirmed (via `.drive_upload.json`)

## Masking (how to mark swatches)

You control what the system samples by drawing/marking in the `_x` image.

Guidelines:
- Mark **only the areas you want swatches from**.
- Bigger marked regions generally produce more stable samples.
- Avoid marking across two very different materials/values (you’ll average them).

### Skin mask flow (recommended for portraits)
If you select **Mask type: Skin** (UI) or use `/palette skin` (Telegram):
- The worker will treat all extracted swatches as “skin swatches”
- It will combine them into a single **local skin base** color (Lab mean)
- It will generate one recipe for that local skin base

Artifacts:
- `/mnt/out/BASE/BASE_local_skin.json`
- A PDF page titled: `BASE — Skin Local Color`

## Outputs

### PDF report
`/mnt/out/BASE/BASE_report.pdf`

Contains (depending on config):
- bounding-box/marked overview
- per-swatch pie chart showing paint percentages
- optional palette swatch page(s)
- optional originals at end

### Charts
`/mnt/out/BASE/charts/`
- pie chart images for each swatch

### Palettes
`/mnt/out/BASE/palettes/`
- palette swatch images for each target hex

### Drive upload marker
`/mnt/out/BASE/.drive_upload.json`
- written only after a successful upload
- used by the Telegram bot and job page to confirm upload

## Web UI tools

### Paint palette editor
`/paints`
- Add/edit/reorder paints
- Enable/disable paints

Config is written to:
- `[paints]`
- `[paints.enabled]`

### Local color tool
`/local-color`
- Paste multiple hex codes (comma-separated)
- Computes a combined base (Lab mean) + suggested mix

### Skin deltas (add-only “parts” guidance)
`/runs/<base>/skin-deltas`

Goal: help you start from the **skin local mix** and reach each swatch by **adding paint**.

Requirements:
- `BASE_local_skin.json` (generated by skin mask run)
- `BASE_mix.json` (generated only if `write_mix_json=true`)

How it works:
- Computes the target swatch mix
- Computes a “start with X parts of local mix, then add Y parts of paints” plan

Notes:
- This is guidance. Real paint behavior isn’t perfectly linear.

## Configuration (INI)

The main INI file controls:
- paths (input/output/archive)
- watcher polling
- diff threshold
- mixing parameters
- drive upload
- paints

See:
- `config/color_palette_config.ini.example`

Important keys:

```ini
[outputs]
# if false, palette swatch pages will not appear in the PDF
build_palettes=true

# if false, palette page shows base-only rather than variants
palette_include_variants=false

# needed for /runs/<base>/skin-deltas
write_mix_json=true

[mix]
step_pct=2.5
max_pigments=4

[paints]
Titanium White=#FFFFFF
...

[drive]
enabled=false
remote=palette_drive
mode=full_folder
```

## Docker / Deployment

This repo is portable via `.env`.

Quick start (local defaults):
```bash
cp .env.example .env
cd docker
docker compose up -d --build
```

For a NAS deployment, set these in `docker/.env` (example):
- `INCOMING_DIR=/path/to/incoming`
- `PROCESSED_DIR=/path/to/processed`
- `ARCHIVE_DIR=/path/to/archive`
- `CONFIG_FILE=/path/to/color_palette_config.ini`
- `RCLONE_CONFIG=/path/to/rclone.conf`
- `UI_PORT=4040`

## Troubleshooting

### “Nothing is happening”
- Make sure both files exist and match base naming:
  - `BASE.jpg` and `BASE_x.jpg`
- Confirm the worker container is running.

### “Drive upload never confirms”
- Check that `[drive].enabled=true`
- Ensure the worker container has access to `rclone.conf`
- Look for `.drive_upload.json` in the output folder

### “Skin deltas page is empty”
- Ensure `write_mix_json=true`
- Run a new job with mask type **Skin** so `BASE_local_skin.json` exists
